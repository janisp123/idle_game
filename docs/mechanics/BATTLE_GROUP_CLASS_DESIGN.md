# BATTLE-GROUP-RESEARCH-001 — 31 specializations, design proposal

Date: 2026-11-27. Baseline 7eacc796aa0efead1e258511198b0e4b002d1ac1. Branch research/battle-group-interlude. Owner requested full original design matrix following the five-race/31-final-profession Interlude model. Research/design only; no implementation, numbers or names approved yet.

## Evidence and boundaries

The Interlude indexes agree on 31 final professions across five races (11 Human, 7 Elf, 7 Dark Elf, 4 Orc, 2 Dwarf). Original progression has a starting archetype and three transfers; our main-class branch simplifies the level-20 path, directly selecting a final specialization. The original separate subclass mechanic is out of scope. No later Kamael or certification/skill-transfer/chain-heal mechanics. Source comparison used class indexes, patch-note archive, stat table and selected class-specific pages; not an exhaustive verification of every original skill rank or exact equipment mastery. No numerical values or copied skill names/description text are proposed. Generic fantasy race names and suggested specialization labels are provisional and require naming clearance before publication. Original profession labels below are research references only.

## Proposed race identities

Human: balanced physical/magic profiles. Elf: mobility and cast efficiency in exchange for raw power. Dark Elf: offensive power in exchange for durability. Orc: physical strength/endurance, less finesse. Dwarf: durability and engineering utility, lower mobility. These are qualitative archetypes, not bonuses. Keep relative costs bounded; use the same stats and formulas for players and rivals. Verify all roles remain useful at equal endgame progression.

## Shared combat architecture, not 31 special-case engines

- Seven roster slots from first entry (proposal: all 31 specializations selectable without level-based unlock chores); repeat classes legal. Race/main class/specialization/stance are the only strategic inputs. Main class groups selection; specialization chooses data-defined actions, equipment, and preferred positioning. No player selects gear pieces or commands turns. No mandatory tank/healer composition. Allow reversible class changes while retaining inactive choice progress; exact race-change rules and gear-sharing between classes require owner decision. Proposed class-specific gear/mastery so changing a role does not create free trained gear.
- Equipment uses existing sequential grades and quality where applicable, automatic buying/upgrading under a common treasury. New weapons (dual swords, dagger, gauntlets, axe, wand/staff/scepter) and cloth armour use shared damage, guard, durability and upgrade schemas. Do not blindly transfer current five-weapon numbers. Keep weapon/armour/class/stance progress tied to active use; noncombat activities remain automatic. Seven-member prices, coin reward and XP budgets need new validation, not multiplication by 7/2.
- Introduce mana and shared action rules for casting, movement, recovery, healing, shields, buffs, debuffs, taunts/guards, interrupts, cleansing, summoning and reviving. Existing STR/DEX/END only model physical progression; decide whether to add a magic attribute or use class mastery before setting formulae. Every skill references common effect primitives, targeting priority, cost, cooldown, range, duration, tags and resistance. No instant-win skills. Status immunity/diminishing returns, finite resources and bounded resurrection/summons prevent endless loops. Summons consume owner action/resource budget and never occupy an eighth selectable fighter slot or generate independent progression. Same rules for enemy/player. Nonstacking buff families and bounded mitigation; different families can complement within tested limits. Healing has no overheal rewards and cannot generate mana; mana transfers must not create infinite cycles. All exact values and limits await simulation.
- Stances change priorities, not generic bonuses: aggressive prioritizes damage, attack support, closing distance and debuffs; balanced prioritizes role-appropriate effectiveness and safety; defensive prioritizes protection, sustain, spacing and conservative resources. Healers remain healers in all stances. All build decisions frozen before unknown terrain. Role-based initial placement is automatic; later formation controls need explicit approval.
- Rival generation from comparable earned progression; sample independent race/class/stance choices. Early random/exploratory choices; toward endgame diverse coherent combinations based on independent simulation holdouts (not omniscient counter-picks or preknown location). No forced win rate. Existing bounded deterministic offline schedule and frozen-session invariants remain. Current runtime max roster is six and active roster two; this is a substantial engine migration, not a UI-only change.
- UI: one foldable Battle Group editor, 7 slot buttons with class/role/stance, then three-level class selector and stance. Auto gear summary, short plain-language "strong against / weak against / works with" descriptions and what each stance does. Arena shows roster role/class icons, actual terrain, progress, verdict; no narration or tiny moving HP bars. Analytics retain old history separately, add class/race presence, role counts, stance, terrain, own setup, sample sizes and exact coin/hour. Seven slots have many possible compositions; bounded aggregate analytics must not store all combinations.
- No new server or shared player telemetry in this phase; only local battle analytics and developer-only simulator until approved separately.

## Endgame-first validation plan

No numerical tests run. Original 31 classes × 3 stances = 93 individual builds before gear progression; ordered seven-slot enumeration is infeasible. Use max-only S Masterwork and equal earned mastery/attributes/teamwork first; later scale lower tiers after owner approval. Candidate test design: mirrored side-swaps; all 31 classes represented across diverse rosters; seeded stratified sampling by role count/race/stance, 5 arenas, fixed opponent pools, repeats, independent holdouts, compare both side orientations. Check each class's marginal value as a substitution in different contexts; look for counters and stable strongest groups, not just overall win percentage. Record wins/loss/draw, action contributions, healing prevention, mana, uptime, survival, turns, terrain sensitivity, payoff/hour, simulation cost and offline partition equivalence. Use rare-class and duplicate-class stress cases, bounded summon count, no permanent stun/infinite healing/buff loops. Don't declare balance from one sample; preserve source-backed reproducible results. Exact max magic stat and mastery benchmark to be designed; don't silently invent a new cap. Compare current endgame results only as historical reference, not direct 7v7 calibration.
