# AUTO-FIGHT-02 — deterministic policy foundation
2026-11-26, branch research/auto-fight-policy-001, draft PR #183. Baseline main de5853ae0252f2cba1c888a04359fb92bc0b6c83. Owner approved continuation. The prior production validation selected 3/1/10 provisionally for initial implementation.

## Implemented (not wired into gameplay)
`site/play/auto-fight.mjs` exports initialAutoFight(stage), validAutoFight, requiredAutoFightWins and finishAutoFightBout(progress,outcome,online=false). State is {stage,streak,blocked,highest}. Initial stage NG, history -1; both loss outcomes retreat by one, reset streak and record the failed grade. At the floor stay NG; at S no further advance or streak growth. Three consecutive wins advance normally, ten consecutive wins to reattempt the most recently failed grade. Historical highest records only actually defeated opponents and survives retreats. No early-retry reset on gear changes. Offline (including omitted online flag) returns the same object unchanged. Invalid stage/counter/outcome/mode rejected. Pure deterministic function; callers are responsible for passing a genuinely live, committed, completed bout exactly once. No wallet or combat formulas copied.
