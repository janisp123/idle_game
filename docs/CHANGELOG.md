### Batch A0 — Measure the broken baseline before tuning (2026-11-25, chat)

**Why:** The Owner wants one fully mastered build after roughly six months, not an S-grade item in the first month. Current shop prices, 10-second alpha XP cycles and the existing level gate can conceal major normal-timing economic problems. Changing prices, expertise or damage before measuring this baseline would make later results impossible to attribute. Therefore this batch changes **developer tooling only**, leaving the playable site, gear and saved games untouched.

**Source findings before running:** Current normal Fighting cycles are 20 minutes, alpha cycles 10 seconds; arena bouts are 200 seconds in both. Fighting awards 100 shared attribute XP per productive hour at weights 35/35/30, each Master claim adds one attribute point; XP caps at one level until claimed. The old smith has no Fighting purchase requirement and cumulative S Masterwork costs 1,099 coins per weapon, 1,123 per previously unowned armour piece, or 5,591 for a full weapon + four-piece build. Non-grade rewards 12 per win, theoretical 5,184/day at 100% wins, **not an observed income**. High-tier arena difficulty is presently locked by level, contrary to new approved direction.

**What:** `tools/simulation/build-progression.mjs` exercises actual engine settlement, combat prizes, Master claims, smith quotes and purchases, gear selection, activity transitions and attribute calculations. It runs each profile through a disposable module copy, changing only the sanctioned timing-profile constant (never published source). Four transparent strategies: daily and weekly single-build players, daily 5:2 Fighting/mining, and first-month hourly low-tier S-rush. Output checkpoints day 0/30/90/150/180, actual wins/losses/double deaths, stats, Fighting, productive hours, coins, purchases and earliest *observed* affordability. Expertise is null because it does not exist yet. This is a fixed-seed baseline, not an optimal search or statistical confidence interval.

**Alternatives:** Rejected estimating coins from 100% wins or copying combat / progression formulas into a separate spreadsheet; rejected editing the live timing switch to measure normal behavior. Existing developer system lab is used for bounded deterministic smoke checks; its workflow runs the full baseline only on this active balance branch, with a JSON artifact and log summary (remove branch-specific report step at closeout or replace with an explicitly approved manual benchmark later; no new permissions). Smoke test covers normal/alpha separation, reproducibility, wallet and outcome conservation. Full benchmark is separate from routine small tests.
